# v1.5.2 — Halaman produk dan Pengaturan toko

Halaman produk dan Pengaturan mengikuti mockup mobile/desktop dengan data toko sebenarnya. Tidak ada migrasi database, perubahan dependency, DNS, onboarding, installer, atau kontrak pengiriman/pembayaran.

| Before | After | Why |
| --- | --- | --- |
| Informasi dan aksi produk tersebar | Galeri dengan zoom/counter, informasi ringkas, pilihan dinamis, deskripsi lipat, Q&A dan rekomendasi | Produk mudah diperiksa pada mobile dan desktop |
| Pilihan belum lengkap kurang jelas | Feedback menyebut atribut yang kurang dan memfokuskan pilihan; stok tetap divalidasi | Tidak membuat perubahan keranjang/checkout dengan kombinasi tidak valid |
| Kontak toko belum dipisahkan | WhatsApp publik, toggle, jam layanan dan pratinjau memakai konfigurasi tersimpan | Nomor pribadi seller tidak dipublikasikan otomatis |
| Pengaturan tersebar di menu utama | Submenu Pengaturan dengan kartu identitas dan layanan pelanggan | Navigasi desktop dan mobile konsisten dengan mockup |
| URL lama memiliki halaman terpisah | Redirect ke URL kanonis dengan query dipertahankan | Bookmark lama tetap berfungsi |

## Pengaturan

Menu utama: Dashboard, Dekorasi Toko, Produk, Pesanan, Pelanggan, Promosi, Inventori, Pembayaran, Pengaturan. Kategori berada di Produk; konfigurasi pengiriman, bank, metode pembayaran, Email & OTP, keamanan, audit dan update versi berada di Pengaturan. Pembayaran operasional tetap terpisah dari konfigurasi.

Informasi Seller hanya mengubah nama akun yang sedang masuk. Email/nomor pribadi tetap melalui mekanisme identitas terverifikasi. Informasi Toko mengelola nama, logo, deskripsi, alamat operasional dan WhatsApp publik. Alamat operasional tidak mengubah gudang J&T. Logo menggunakan pipeline upload dan pemeriksaan aset existing.

Penyimpanan menggunakan izin publish existing, pemeriksaan versi dan audit. Draft dekorasi lain tidak diterbitkan diam-diam. Form mempertahankan masukan saat gagal dan memperingatkan perubahan belum disimpan. Link WhatsApp memakai host tetap `wa.me`, nomor internasional tervalidasi dan URL produk bersih; tidak mengirim pesan otomatis.

## Identitas email

Jika relay aktif, perubahan nama pengirim memerlukan registry relay operator yang sesuai. Pemeriksaan status dilakukan sebelum perubahan diterbitkan, termasuk jalur publish/rollback Dekorasi Toko. Jika registry belum cocok, penerbitan nama baru ditolak dengan pesan jelas; kredensial tidak dikirim ke browser. Nomor WhatsApp, deskripsi, jam layanan dan nama seller pribadi tidak mengubah registry email. Tidak ada pengiriman email nyata pada rilis UI ini.

## Deployment dan rollback

Baseline Hubify v1.5.1: `03c306bab048d2abd34755fc2779c2331b6dd26e`. Semua 25 checksum migrasi tetap identik. Paket resmi diverifikasi berdasarkan SHA, manifest dan digest; restore backup diuji ke database sementara. Build disiapkan saat versi lama tetap melayani trafik, kemudian hanya container aplikasi Hubify diganti. Environment, konfigurasi proxy bersama, ledger transaksi dan service platform/relay harus tetap sama.

Walau tidak ada migrasi SQL, konfigurasi identitas JSON kini memiliki field baru. Parser ketat versi lama tidak mengenali field tersebut setelah konfigurasi baru disimpan. Karena itu `rollback_compatible: false` dipertahankan. Helper operator hanya mengizinkan rollback image v1.5.1 selama field konfigurasi baru belum tersimpan. Sesudahnya gunakan perbaikan maju yang kompatibel; jangan menghapus field/config atau memulihkan database lama untuk memaksa rollback.

Journal `/etc/single-store/hubify-v152.json` menyimpan image sebelumnya, backup, ledger dan hasil smoke. Helper `/var/lib/single-store/hubify-v152-deploy.py rollback` memeriksa kompatibilitas sebelum mengubah image. Backup dan image sebelumnya dipertahankan; volume tidak dihapus.
