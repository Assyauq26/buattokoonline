# v1.6.0 — Flow pesanan sederhana dan daftar ringkas

## Audit dan keputusan
Baseline Hubify: v1.5.6, commit fbf7017e32b2948a6ac4536a6204b7ecc8b22d3e, 25 migrasi. Worker single-store-maintenance.timer sudah aktif dan memanggil cron terautentikasi setiap menit. Tidak ada webhook J&T yang dikonfigurasi; tidak menambah webhook atau endpoint pickup yang tidak didukung.

| Before | After | Why |
| --- | --- | --- |
| PAID → PROCESSING → PACKED memakai beberapa tombol/konfirmasi | Satu klik Siapkan paket: PAID → PACKED; PROCESSING lama tetap dikenali sebagai dikemas | Tidak ada penjualan, reservasi atau pengurangan stok ulang |
| Label kartu, detail, dashboard dan customer tersebar | Selector status/tindakan dan predicate query bersama | Count/filter/pagination berdasarkan keseluruhan data server |
| Kartu menonjolkan baris pertama, variasi dan harga satuan | Thumbnail maksimal 3 slot, distinct product ID, total unit dan total transaksi | Produk dengan beberapa varian tidak dihitung ganda |
| Konfirmasi resi generik dan syarat penyerahan seller | Satu modal review; tidak ada tombol penyerahan manual pada UI J&T | AWB, cetak dan pickup adalah fakta berbeda |
| Delivered memerlukan langkah selesai tambahan | Event delivered mencatat DELIVERED lalu COMPLETED jika tidak ada hold finansial | Fakta delivered dan waktu penyelesaian tetap terpisah dalam shipment event/riwayat |
| Retur hanya tersembunyi pada status teknis | Retur memiliki tab dan substatus eksplisit | Return tidak membatalkan transaksi, refund atau restock |

## Status, CTA dan kompatibilitas
- Menunggu pembayaran → Lihat detail / Hubungi pembeli.
- Menunggu verifikasi → Verifikasi pembayaran. Minta perbaikan tetap wajib alasan; customer dapat unggah ulang tanpa otomatis diminta membayar ulang.
- Pembayaran disetujui → Siapkan paket, tanpa dialog konfirmasi tambahan.
- Sedang dikemas → Buat resi melalui modal penerima/alamat/layanan/berat/barang. Harga dan variasi memakai snapshot transaksi.
- Menunggu pickup → Cetak AWB, satu modal ukuran/preview. Cetak ulang tidak membuat resi; penutupan print tidak diklaim telah mencetak.
- Dikirim → Lacak pengiriman.
- Selesai → Lihat detail / riwayat pengiriman.
- Retur → Lacak retur; kode 401 dalam perjalanan kembali, 402 diterima seller menurut kurir. Pemeriksaan barang, keputusan refund dan restock tetap melalui kasus terpisah.
- Dibatalkan → Lihat detail; kewajiban refund tampil terpisah sesuai state nyata.
- UNKNOWN/dispatch/cancel pending dan kegagalan tracking tetap terpisah dari keberhasilan bisnis. Hasil tak pasti tidak di-retry otomatis.

Tab seller: Semua, Pembayaran (3 subfilter), Perlu disiapkan, Dikemas, Menunggu pickup, Dikirim, Selesai, Retur, Dibatalkan. Query dan pagination memakai snapshot transaksi RepeatableRead; tidak memfilter hanya halaman yang sudah dimuat. Summary daftar tidak mengambil tracking, audit atau proof per kartu. Dashboard dan tab customer memakai predicate yang sama sesuai kelompok masing-masing. UI customer tetap memiliki grup Diproses yang menggabungkan fase penyiapan dan menunggu pickup.

Tidak ada perubahan enum atau SQL. Tidak ada bulk update:
- PAID tanpa shipment tetap perlu disiapkan.
- PROCESSING lama diproyeksikan sebagai dikemas; dinormalisasi ke PACKED secara transaksional hanya bila seller meminta create AWB.
- PACKED tanpa AWB tetap dikemas.
- AWB aktif tanpa pickup terkonfirmasi → menunggu pickup, walaupun ada pernyataan handover seller lama.
- AWB dibatalkan → dikemas/perlu resi baru, kecuali transaksi telah dibatalkan/refund penuh.
- Pesanan dibatalkan tidak diaktifkan ulang.
- DELIVERED lama ditampilkan selesai; penutupan COMPLETED baru hanya dari konfirmasi carrier yang cocok, bukan timer atau estimasi.

## Tracking dan operasi carrier
Dokumentasi primer: https://developer.jet.co.id/documentation . Kode 100 menandai pergerakan/pickup, 200 delivered, 401/402 retur, 150–152 kendala (bukan retur). Kode cancel dan ID tersimpan dari v1.5.6 tetap dipertahankan.

Polling berjalan di server meski tidak ada halaman dibuka. Satu shipment paling lama jatuh tempo per run, minimal 24 jam sejak pemeriksaan sebelumnya. Shipment selesai tetap dipantau selama 30 hari sejak pencatatan delivered, atau selama ada kasus aktif, agar retur susulan tidak dihapus. Setelah jendela polling ini, refresh manual tetap tersedia. Jendela polling bukan tenggat hak retur. Kapasitas teoritis maksimum worker adalah 1.440 shipment jatuh tempo per hari; toko lebih besar memerlukan perluasan worker tersendiri.

Event disimpan dengan waktu kejadian provider. Waktu penerimaan baru disimpan dalam audit jnt.tracking.event-received; waktu penerimaan historis yang belum tersimpan tidak dikarang. Deduplikasi menggunakan shipment, deskripsi dan waktu kejadian di bawah row lock. Respons untuk AWB/attempt lama tidak dapat mengubah shipment pengganti. Status fisik tidak diturunkan oleh respons lama; RETURNED tidak kembali menjadi RETURNING/NONE.

Create/cancel tetap menyimpan intent sebelum jaringan dan tidak menahan transaksi selama request. Hanya rejection validasi deterministik yang didokumentasikan dan cocok dengan ID yang mengizinkan retry dengan ID sama. Duplicate ID, timeout dan respons ambigu tetap UNKNOWN. Riwayat resi pengganti dan pembatalan/refund v1.5.6 dipertahankan.

Retur terkonfirmasi setelah delivered pada pembayaran yang masih PAID membuka satu kasus RETURN/REVIEW tanpa nominal refund, tanpa restock dan tanpa menghapus riwayat pengantaran. Jika sudah ada kasus aktif, kasus itu dipertahankan; identitas carrier-return per attempt mencegah duplikasi pada polling/replay. Seller menentukan pemeriksaan dan tindak lanjut finansial.

Notifikasi baru memakai inbox aplikasi yang sudah ada, di dalam transaksi perubahan terkonfirmasi. Replay tidak membuat notifikasi penjualan/packing/pengiriman berulang. Tidak menambah kanal email eksternal, webhook atau transfer otomatis.

## Verifikasi dan rilis
Provider simulasi dipakai untuk create/cancel/pickup/delivery/return. Tidak membuat atau membatalkan shipment nyata, mengirim pesan eksternal, atau memindahkan uang sebagai pengujian.

Pemeriksaan mencakup workflow finansial existing, parallel/replay, satu klik packing, kegagalan/timeout/reconciliation AWB, carrier order identity, penggantian resi, event duplikat/terlambat, daily worker, hold refund, no double-sale/restock, query status, multiproduk lintas varian, jumlah tersembunyi +N, RBAC/origin, tema dan browser 360/390/430/1440.

Rilis minor hanya ke Hubify setelah pemeriksaan lulus. Tidak menjalankan CI, membuat staging, mengubah DNS, installer, onboarding atau platform/relay. Paket mempertahankan 25 checksum migrasi.

## Rollback
Backup diuji restore sebelum pergantian app, simpan image v1.5.6 dan konfigurasi proxy/compose sebelumnya. Rollback kode dengan database/config terkini; jangan restore database lama untuk membatalkan catatan dana, stok atau carrier. Hentikan create/cancel baru sementara bila ada operasi UNKNOWN; rekonsiliasi operasi sebelum retry. Model status/kolom tetap dikenali v1.5.6; intent PREPARED dengan CREATION_REJECTED tetap konservatif pada kode lama sampai operator memperbarui ulang.

Verifikasi lokal: 650 tes lulus dan 3 dilewati; build/typecheck lulus. Browser 28 pemeriksaan pada lebar 360/390/430/1440, termasuk tema monokrom/berwarna, back link beserta state daftar, role/origin, pemrosesan satu klik dan finansial sintetis. Screenshot tersimpan pada folder evidence lokal. Tidak ada dispatch create/cancel carrier atau transfer nyata. Pemeriksaan hasil resi tidak pasti juga lulus: tidak menawarkan create ulang dan rekonsiliasi langsung terbuka. SHA, worker dan smoke produksi dilaporkan setelah pemasangan.
