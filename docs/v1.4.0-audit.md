# Gheverhan v1.4.0 — audit dan rencana validasi

Baseline live dan GitHub diverifikasi v1.3.0, commit 0badbc6be3476781bd7a653c91fe3ab2c3736917. Worktree terpisah; perubahan lama tidak direset.

| Before | After | Why |
|---|---|---|
| Auth CSS merah hardcode dan tautan seller di customer | Token tema backend, pemulihan sesuai konteks | Konsistensi tema dan navigasi |
| Seluruh form akun pada landing akun | Ringkasan profil/pesanan dan pengaturan terpisah | Hierarki ringkas sesuai referensi |
| Loading berbentuk placeholder kontrol | Skeleton inline | Hindari kontrol palsu |
| Filter details dengan ikon besar | Radix dialog bottom sheet | Focus trap, Escape, backdrop, target 44px |
| Cancelled AWB tampil pada customer seperti resi aktif | Status dibatalkan dan penjelasan pengiriman ulang | Sinkronisasi customer dengan state existing |
| HTML label bergantung viewport, nomor penerima lengkap | PDF fixed 100x150mm, mask nomor, logo resmi | Konsistensi cetak dan privasi |

Skill emil-design-eng dibaca penuh sebelum edit. Diterapkan: feedback press singkat, fokus terlihat, tidak menambah animasi daftar/tabs yang sering dipakai; pemisahan hierarki; skeleton tidak berperilaku seperti tombol; dialog dengan interaksi keyboard bawaan; reduced motion untuk kontrol yang bergerak. Tidak mengubah state finansial atau mekanisme OTP.

J&T v1.3.0 telah memiliki request idempotent, archive attempt, cancellation confirmation dan fail-closed UNKNOWN. Pertahankan dan jalankan tes DB/mock; jangan panggil create/cancel carrier produksi untuk QA. Refactor customer hanya mencegah tampilan resi cancelled sebagai aktif.

Rencana: auth/theme → akun dan pesanan customer → filter/kartu seller → sinkronisasi cancel customer → PDF protected endpoint → unit/DB/security/lint/build/browser pada 360/390/430/768/1024/1280/1440/1920 → review PR → release gate. Tidak memerlukan migrasi DB.

Logo diambil dari https://www.jet.co.id/static/images/logo.png?t=1, tidak direkonstruksi dengan teks. PDF menggunakan Times dan barcode/QR dari bwip-js. Panjang data yang tidak muat ditolak dengan 422 alih-alih memotong data operasional. Ukuran 100x150mm merupakan target implementasi; uji printer thermal fisik dan viewer Android tetap harus dilaporkan terpisah.


Security review: recovery customer existing menolak akun seller; permission SHIPPING_READ wajib sebelum load PDF; identitas toko tetap satu instalasi per database. Endpoint PDF tidak menyisipkan nomor penerima asli ke HTML/metadata. Private/no-store dan nosniff digunakan. Semua tindakan order tetap menuju endpoint v1.3.0 yang memverifikasi RBAC/state finansial. npm audit --omit=dev: 0 vulnerabilities. Lint seluruh src: 0 error dengan warning existing untuk img/unused. Tidak ada API key atau perubahan secret.
