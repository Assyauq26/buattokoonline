# v1.5.0 — Kelola pesanan, pembatalan, retur dan refund

Daftar dan detail pesanan seller memakai alur mobile-first sesuai tema toko. Verifikasi pembayaran, pengiriman, pembatalan pesanan, retur dan refund mempunyai tindakan serta status terpisah. Antrean kasus tetap terlihat walaupun pesanannya dibatalkan.

- Bukti transfer dapat diminta perbaikan dengan alasan, tanpa otomatis meminta pembeli membayar ulang.
- Pembatalan resi mempertahankan pesanan, pembayaran dan stok. Respons detail per order diperiksa; hasil ambigu tetap menunggu rekonsiliasi sebelum resi pengganti dapat dibuat.
- Catatan penyerahan seller terpisah dari tracking kurir. Tracking tidak menutup kasus keuangan dan tidak otomatis menyelesaikan pesanan.
- Pembatalan pesanan berbayar sebelum penyerahan membuat kewajiban refund penuh termasuk ongkir. Reservasi/stok dikembalikan tepat sekali.
- Retur/refund sebagian memakai snapshot produk dan alokasi diskon. Barang retur baru menjadi stok jual setelah pemeriksaan eksplisit.
- Rekening tujuan milik pembeli dienkripsi per instalasi dan dikunci sebelum transfer manual. Bukti privat, referensi dan riwayat tersimpan. Klaim seller terpisah dari konfirmasi dana diterima atau laporan belum diterima oleh pembeli.
- Koreksi pencocokan path Windows mengaktifkan backport React produksi yang sudah tersedia; versi framework tidak diganti.

## Instalasi dan upgrade

**Instalasi baru:** skema lengkap diterapkan oleh installer normal. Siapkan Ubuntu 24.04, PostgreSQL 16 dan persyaratan VPS yang tercantum di README. Installer menyimpan kunci enkripsi per instalasi; jangan menyebarkan secret antartoko.

**Toko yang sudah berjalan:** rilis ini memerlukan migrasi operator dan bukan update otomatis biasa. Dua migrasi tambahan adalah `20261109120000_order_resolution_workflow` dan `20261109121500_resolution_transfer_review`. Tabel dan data lama dipertahankan. Jangan menjalankan bootstrap ulang, memalsukan riwayat Prisma, mengganti kunci enkripsi, atau menghapus volume.

`rollback_compatible: false` sengaja menghentikan updater otomatis sebelum downtime. Kode lama tidak mengenali kewajiban refund yang baru dicatat. Metadata ini tidak boleh diubah menjadi `true` untuk memaksa pemasangan. Prosedur backup, uji restore, migrasi dan aktivasi operator ada di [seller-order-resolution.md](seller-order-resolution.md#rollout-and-rollback-operator-after-approval).

## Rollback

Simpan image, database, media, konfigurasi dan kunci enkripsi sebelum aktivasi. Bila belum ada operasi baru, kode sebelumnya dapat dipulihkan dengan pemeriksaan operator. Setelah kewajiban refund/retur baru ditulis, pertahankan ledger dan hentikan writer lama: gunakan perbaikan maju atau build kompatibel yang menghormati hold baru. Jangan memulihkan database lama secara buta karena kewajiban pengembalian dana dapat hilang.

## Bukti dan batasan

586 tes aplikasi/integrasi lulus; 3 tes filesystem khusus Linux dilewati pada host Windows. Build produksi dan typecheck lulus. Browser alur pesanan: 24 pemeriksaan, 19 screenshot pada lebar 360–1440 px, tanpa error runtime. Regresi manajemen existing: 66 pemeriksaan lulus. Lint: 0 error, 35 warning.

Pengujian menggunakan PostgreSQL lokal terisolasi dan provider mock. Tidak ada resi J&T nyata yang dibuat/dibatalkan dan tidak ada transfer bank nyata. Unggahan bukti tidak berarti transaksi telah diverifikasi bank. Pengujian perangkat/printer fisik tidak diulang untuk rilis ini.

Penerbitan paket/tag tidak mengaktifkan aplikasi pada Hubify atau VPS seller. Deployment produksi dan smoke test harus dilaporkan terpisah; rilis ini tidak mengubah DNS atau membuka onboarding baru.
